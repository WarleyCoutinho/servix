### 7. Integração com Stripe – Revisão de Estabilidade e Webhooks

Revisar o arquivo e depois fazer os ajustes no sistema baseado no arquivo que está aqui @/docs/Guia_configuracao_stripe.md e depois atualizá-lo caso necessário.

**Prompt de Avaliação do Código:**

Você é um especialista em integrações com Stripe. Analise todo o código de integração com Stripe neste projeto e faça uma revisão completa seguindo as instruções abaixo:

---

**1. Revisar o Webhook Handler**

Verificar se a rota que recebe os eventos da Stripe está implementada corretamente:

- A assinatura do webhook está sendo validada com `stripe.webhooks.constructEvent` antes de processar qualquer evento?
- O `rawBody` está sendo lido corretamente antes de qualquer parsing JSON? (Erro comum que quebra a validação da assinatura)
- Existe tratamento de erro caso a assinatura seja inválida?
- A rota retorna `200` imediatamente após receber o evento, antes de processar a lógica de negócio? (Stripe requer resposta rápida para não reenviar o evento)

**2. Revisar os Eventos Implementados**

Confirmar se todos os eventos abaixo estão sendo tratados corretamente e salvando os dados no banco:

Eventos de Assinatura:

- `checkout.session.completed` → salvar customerId, subscriptionId, status, plano e data de início.
- `customer.subscription.created` → salvar subscriptionId, status, plano, período de cobrança.
- `customer.subscription.updated` → atualizar status, plano e datas no banco.
- `customer.subscription.deleted` → marcar assinatura como cancelada no banco e bloquear acesso à plataforma.
- `invoice.paid` → registrar pagamento, atualizar data de vencimento e manter assinatura ativa.
- `invoice.payment_failed` → registrar falha, notificar profissional e iniciar fluxo de inadimplência.

Eventos de Conta do Profissional (Connect):

- `account.updated` → verificar `charges_enabled`, `payouts_enabled` e `details_submitted`. Atualizar status da conta no banco. Se todos forem `true`, marcar conta como ativa na plataforma.
- `account.application.deauthorized` → revogar acesso do profissional à plataforma e notificá-lo.
- `payout.paid` → registrar repasse realizado com sucesso.
- `payout.failed` → registrar falha no repasse e notificar profissional.

Eventos de Pagamento:

- `payment_intent.payment_failed` → registrar falha, notificar cliente e profissional.
- `charge.refunded` → registrar estorno, atualizar status do agendamento e notificar cliente.

Eventos adicionais recomendados a verificar se estão faltando:

- `payment_intent.succeeded` → confirmar pagamento do agendamento e liberar o slot.
- `customer.subscription.trial_will_end` → notificar profissional 3 dias antes do trial expirar.
- `invoice.upcoming` → notificar profissional sobre cobrança futura.
- `account.external_account.created` → confirmar que conta bancária foi adicionada com sucesso.

**3. Revisar o Fluxo de Ativação da Conta do Profissional**

- Após o profissional preencher todos os dados na Stripe, o sistema está aguardando o evento `account.updated` para ativar a conta?
- Está verificando os três campos obrigatórios: `charges_enabled`, `payouts_enabled` e `details_submitted`?
- Se algum desses campos for `false`, a conta deve permanecer pendente e o profissional deve ser notificado para completar o cadastro.
- O banco de dados está sendo atualizado corretamente com o status da conta após cada evento?

```typescript
// Exemplo do fluxo correto de ativação
if (
  account.charges_enabled &&
  account.payouts_enabled &&
  account.details_submitted
) {
  // conta ativa – atualizar no banco e liberar acesso
} else {
  // conta pendente – notificar profissional para completar cadastro
}
```

**4. Revisar Idempotência**

- Existe verificação para evitar processar o mesmo evento duas vezes? (Stripe pode reenviar eventos em caso de falha)
- Sugestão: salvar o `event.id` no banco e verificar se já foi processado antes de executar qualquer lógica.

```typescript
// Exemplo de verificação de idempotência
const alreadyProcessed = await db.stripeEvent.findUnique({
  where: { eventId: event.id },
});

if (alreadyProcessed) return reply.status(200).send({ received: true });

await db.stripeEvent.create({ data: { eventId: event.id } });
// processar evento...
```

**5. Revisar Tipagem**

- `strict: true` deve estar habilitado.
- É proibido o uso de `any`, `unknown` solto, `@ts-ignore` ou `@ts-expect-error`.
- O objeto `event.data.object` deve ser tipado corretamente com os tipos do SDK da Stripe:

```typescript
// Correto
import Stripe from 'stripe'

case 'customer.subscription.updated': {
  const subscription = event.data.object as Stripe.Subscription
  // ...
}
```

**6. Relatório Final**

Após a análise, gerar um relatório com:

- O que está implementado corretamente.
- O que está faltando ou implementado de forma incorreta.
- Quais eventos estão ausentes e precisam ser adicionados.
- Quais dados não estão sendo salvos corretamente no banco.
- Sugestões de correção cirúrgica para cada problema encontrado, sem reescrever o que já funciona.
- Como já está conectado à Stripe, atualizar o documento de integração conforme está aqui no sistema, atualizando o docs para que fique registrado e o passo a passo caso queira fazer uma nova integração @/docs/Guia configuracao stripe.md
