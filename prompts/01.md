# Prompt 1 — Página de Marketing com Acesso Restrito por Autenticação

A página `/` localizada em `app/marketing/page.tsx` deve seguir as seguintes regras de acesso:

1. **Acesso permitido:** Apenas para usuários que NUNCA fizeram login na plataforma (sessão inexistente / nenhum token válido).
2. **Acesso bloqueado:** Qualquer usuário autenticado com as roles `cliente`, `admin`, `owner` ou `profissional` NÃO pode acessar essa página novamente após ter feito o primeiro login.
3. **Comportamento esperado:**
   - Se o usuário não estiver autenticado → exibe a página de marketing normalmente.
   - Se o usuário estiver autenticado (qualquer role) → redirecionar automaticamente para o dashboard correspondente à sua role, sem permitir visualização da página de marketing.
4. **Regra do primeiro acesso:** A página de marketing pode ser vista uma única vez — até o momento em que o login é realizado com sucesso pela primeira vez.
5. **Botões de CTA** ("Começar agora", "Ver como funciona"): ao serem clicados, devem verificar o estado de autenticação antes de redirecionar. Se já autenticado, redirecionar direto para o dashboard, nunca para a página de marketing.
6. **Remover toda a navegação interna** da página de marketing (menus, links de navegação), pois essa página só existe para usuários não autenticados e não deve conter rotas que levem de volta a ela.

# Prompt 2 — Agendamento via Chatbot com Mesmo Fluxo do Sistema

O fluxo de agendamento realizado pelo chatbot deve replicar exatamente o mesmo fluxo do agendamento tradicional já existente no sistema, com a única diferença sendo a interface (chat ao invés de telas/formulários).

Regras:

1. O chatbot deve seguir os mesmos passos do agendamento convencional, na mesma ordem.
2. As validações, regras de negócio, disponibilidade de horários e confirmações devem ser idênticas às do fluxo tradicional.
3. Nenhuma etapa do fluxo original pode ser pulada ou simplificada sem aprovação — o chatbot é apenas uma interface alternativa, não um fluxo simplificado.
4. O resultado final (agendamento criado) deve ser registrado da mesma forma no banco de dados, como se tivesse sido feito pelo fluxo tradicional.

# Prompt 3 — Exibir Nome do Profissional no Chat (não o ID)

No fluxo de agendamento via chatbot, na etapa de seleção do profissional:

1. Ao listar os profissionais disponíveis, exibir o **nome do profissional** ao usuário, nunca o ID.
2. Internamente, o sistema pode (e deve) utilizar o ID para processar a seleção, mas a apresentação visual no chat deve ser sempre o nome legível.
3. Exemplo de formato esperado na mensagem do chat:
   - ✅ "Escolha um profissional: João Silva, Maria Souza, Carlos Lima"
   - ❌ "Escolha um profissional: id_abc123, id_def456"
4. Após o usuário selecionar pelo nome, mapear internamente para o ID correspondente antes de prosseguir para a próxima etapa do fluxo.

# Prompt 4 — Remover Navegação Completa da Página de Marketing

Remover toda e qualquer navegação presente na página de marketing (`app/marketing/page.tsx` e seus componentes filhos):

1. **Remover:** menus de navegação, headers com links, footers com rotas internas, links para outras páginas da plataforma.
2. **Motivo:** A página de marketing só existe para usuários não autenticados. Uma vez autenticado, o usuário nunca mais deve ser direcionado para ela, tornando sua navegação interna desnecessária e indesejada.
3. **Manter apenas:** CTAs de conversão ("Começar agora", "Criar conta", "Fazer login") que direcionam o usuário para o fluxo de autenticação.
4. Garantir que nenhuma rota interna da aplicação redirecione usuários autenticados de volta para `/` (marketing).
